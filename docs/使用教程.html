完整使用教程

从一台设备目录出发，把「评测资料 → XTS 测试 → 豁免草稿 → 报告复审」走完。

适用版本 v1.0.1 Windows 桌面版 只保存草稿，不代提交 最后更新 2026-11-26
先记住三条规矩。
  1. 应用只保存草稿，平台上的「确认提交」始终由你手动点。
  2. 所有路径都点右侧按钮用系统对话框选，不要手填（手填框是只读的）。
  3. 一台设备一个目录；有屏/无屏由该目录下的申请资料决定，不由你在界面上选。

交互式引导

不想读文档？直接点下面按钮，在模拟界面里一步步走完整条流程：高亮会指出每个按钮在哪，你只管点「下一步」。

键盘：← → 翻页，Esc 退出。进度存在本机，下次接着看。

三个最容易搞错的地方，先在这里试一遍

试算：这次复审能不能提交？

勾几下就知道：无屏不会因为缺 DCTS / VALIDATOR 而阻塞，但「没跑到」和「未豁免」一定会。

五分钟跑通一次提交

第一次用照这个顺序走，后面每台设备重复第 3、4 步即可。

  1. 登录：输入平台账号密码，验证通过后凭据会加密保存在本机，下次自动登录。
  2. 选设备目录：到「评测资料」页，点「选择文件夹」选到设备目录（例如 D:\ohos\XTS6.1\DHong\DH-76BC-HL4）。识别到工作簿后会带出豁免资料路径与固件包路径。
  3. 评测资料预检 → 提交：预检会把产品定义、软件定义、报告、联系人逐项核对；通过后点「评测资料提交」，应用走完五步并停在「未提交」状态。
  4. XTS 自动测试：到「XTS 自动测试」页，选设备、勾要跑的套件，点「开始测试」。跑完报告自动归档到 <设备目录>\report\<套件>\report-N，失败的模块会自动补测。
  5. 豁免资料：失败的模块要豁免时，到「豁免资料」页选 exemption 目录 → 「识别目录」看分类和提交路径 → 「豁免资料预检」→ 「保存豁免草稿」。同样只存草稿。
  6. 报告复审：到「报告复审」页点「开始复审」，确认套件跑全、失败项都有豁免，看到「可以提交」再回平台手动提交。

环境与目录约定

应用不自己造目录结构，它按已有约定去找文件。搞清这四样东西，后面每一步都顺。

3.1 一个设备目录长这样

DHong\DH-76BC-HL4\
├─ OpenHarmony兼容性申请资料.xlsx      ← 产品定义 + 「是否带屏」，决定跑哪套最小测试集
├─ report\                             ← XTS 报告归档（应用写入）
│  ├─ ACTS\report-1\ …
│  ├─ ACTS-VALIDATOR\report-1\
│  ├─ HATS\report-1\
│  ├─ DCTS\report-1\
│  └─ SSTS\report-1\
├─ exemption\                          ← 豁免资料（你准备，应用只读）
│  ├─ Acts\<模块>\<套件>.txt
│  ├─ ActsValidator\<套件>\<套件>.txt
│  └─ HATS\<模块>\<模块>.txt
└─ 固件包.zip / .7z                     ← 型号-8位日期命名

3.2 测试用例根目录

「测试用例路径」指向 xts-acts 套件根，里面要有 ssts\ hats\ dcts\ acts\ 四个子目录，例如 D:\ohos\XTS6.1\testcase。

选到套件目录（如 …\testcase\ssts）也能用，应用会自动归一到套件根，并在结果里回显归一结果。

3.3 标准最小测试集

最小测试集目录要和 testcase 同级，应用按屏类型自动挑：

目录用途ACTSHATSDCTS
标准最小测试集_有屏_支持JS应用_6.1LTS版本带屏设备981 模块178 模块13 模块
标准最小测试集_无屏_支持JS应用_6.1LTS版本无屏设备382 模块167 模块不适用

3.4 运行依赖

HDC

连设备用。默认从 PATH 找，也可以在环境变量 OH_XTS_HDC 指定完整路径。

Python + xdevice

跑测试用。应用在开跑前自检 xdevice / ohos 能否 import，缺了会按套件 tools\ 下的离线包重装。

浏览器

评测资料、豁免草稿是真实浏览器操作，用系统已装的 Edge 或 Chrome，不需要额外下载。

登录与账号

应用启动先过登录门，登录成功才会出现左侧导航。

  • 账号密码存在本机用户数据目录，用 0600 / DPAPI 加密，不上传、不写日志。
  • 支持多账号：登录页可切换已保存账号，侧边栏底部「退出账号」会清掉当前会话（不清密码）。
  • 平台若弹验证码 / 短信验证，应用会直接停下并截图留证，不会尝试绕过；这时在浏览器里手工完成验证后再重试。

测试盒子与设备

DCTS 需要测试盒子与设备组网；其他套件只需要被测设备在线。

  1. 接上设备与盒子，确认 hdc list targets 能看到它们。
  2. 「测试盒子」页：填盒子 SN 或 IP:Port，点「连接」/「配网」完成盒子侧配置。
  3. 确认设备空闲：首页与测试页只列空闲设备；被占用的设备不会出现在可选项里。
盒子 SN 不是被测设备 SN。应用会从设备列表里剔掉盒子，避免把盒子当被测设备跑测试。

评测资料提交

把设备目录里的工作簿、报告、固件交给平台，走完五步停在「未提交」。

6.1 填两个东西

  • 账号 / 密码：沿用登录凭据，密码留空表示用已保存的。
  • 设备目录：点「选择文件夹」。也支持选一个批量父目录，应用会递归找下面的设备工作簿逐台处理。

6.2 预检与提交

  1. 评测资料预检：只读检查，不写平台。会核对工作簿字段、报告路径、自检表、固件包是否齐。
  2. 评测资料提交：真实浏览器操作，依次保存「联系人 → 产品定义 → 软件定义 → 报告上传 → 样机寄送」，最后停在「未提交」。
  3. 平台核验：提交后可点「平台核验」回读草稿，确认字段落库正确。
应用永远不点「确认提交」。草稿存好之后，剩下的确认动作请在平台上手动完成。

XTS 自动测试

串行跑 SSTS → HATS（含 HDF 增量）→ DCTS（仅带屏）→ ACTS，失败自动补测，报告按轮归档。

7.1 两个路径

  • 测试用例路径：…\XTS6.1\testcase（套件根，见 3.2）。
  • 设备目录：报告归档根，报告写到 <设备目录>\report\<套件>\report-N。

7.2 有屏 / 无屏不用你选

应用读设备目录下 OpenHarmony兼容性申请资料.xlsx 的「是否带屏」决定方案，并据此选用对应最小测试集。目录里没有工作簿时（例如填的是批量父目录）才退回用 hidumper 探测，结果里会写清来源。

7.3 套件怎么排

套件模式说明
SSTS任务模式整跑单机执行，取第一台 SN；约 23 模块 / 82 用例。
HATS最小集清单带屏 178 模块；其中 3 个 HDF 输入模块拆成「HATS-HDF 增量轮」单独跑、单独归档。
DCTS最小集清单仅带屏；跑前会先解绑盒子与被测设备的历史连接，再做 dcct 组网。
ACTS最小集清单带屏 981 模块 / 无屏 382 模块，模块间并行。

7.4 增量补测

每轮结束后按 summary_report.xml 判卷：失败模块、以及没跑完或被标记 unavailable 的模块，自动进入下一轮补测，最多补 2 轮。仍然失败的模块会标红，提示你去走豁免。

7.5 停止与后台

  • 点「停止测试」会写一个 STOP 标记：当前 xdevice 被结束，已完成模块的报告照样归档，然后状态回到空闲。
  • 关窗口只是收进托盘，测试继续跑；从托盘菜单「显示主界面」可以回去看进度。
跑测试前请关掉别的自动化。同一台设备同时跑两套 XTS 会互相抢 hdc 与屏幕，结果不可信。

镜像固件上传

把固件传到平台「企业空间 → 镜像管理」，评测资料提交时会按文件名选用它。

  • 固件包路径：可以选单个 .zip / .7z，也可以选包含固件的目录。
  • 文件名建议 型号-8 位日期；目录里有多份固件时，文件名含 8 位日期的优先。
  • 上传前会查重：平台已有同名固件就跳过并显示原上传时间；同名但未完成（<100%）会沿用该记录续传。
先传固件、再提交评测资料。资料提交第 4 步要按文件名在平台镜像库里选刚上传的那份。

豁免资料

把 exemption 目录下的报告解析成平台草稿，一条失败项一份草稿。

9.1 三步

  1. 识别目录：只本地解析，不联网。列出每条资料的分类（ACTS / ACTS-Validator / HATS / DCTS / SSTS）、模块、用例数、平台提交路径，以及资料有什么问题。
  2. 豁免资料预检：真浏览器登录平台，只查重、不建草稿。
  3. 保存豁免草稿：逐条创建草稿并保存，不提交。

9.2 资料怎么放

exemption\
├─ Acts\<模块>\<套件>.txt              ← 文件名 = 套件名
│  ├─ evidence\…                        ← 佐证（报告摘录 / hilog）
│  └─ <套件>-豁免材料.zip               ← 附件优先级 zip → pdf → txt
├─ ActsValidator\<套件>\<套件>.txt
└─ HATS\<模块>\<模块>.txt               ← 模块级豁免：写「模块级豁免：<模块> 全部用例」
  • 分类由目录结构识别，不再手填。
  • 报告正文分三节：1. 失败用例 / 2. 失败原因 / 3. 申请豁免理由。若第 3 节只是一句「附件说明：xxx.docx」，应用会改用第 2 节做豁免原因。
  • 用例行支持三种写法：- 模块#套件#用例、模块#套件#用例、失败用例：模块#套件#用例。

9.3 两条会拦住你的校验

测评编号必须与设备资料一致。应用会读设备目录下 OpenHarmony兼容性批量结果_*\result.json 记录的编号；和你在页面填的不一致会直接拒跑，避免把 A 设备的草稿挂到 B 设备的认证记录下。

平台会吃掉尖括号。豁免原因里的 <1500 这类写法，平台会把 < 当标签过滤掉，导致回读不一致。应用在填表前会换成全角 ＜，不影响语义。

报告复审

提交前的最后一道自检：套件跑全没有、失败项有没有豁免。

  1. 选设备目录（要含工作簿、report\、exemption\），点「开始复审」。
  2. 看「结论」：可以提交 表示无阻塞；否则会写清阻塞原因。
  3. 看「套件明细」：期望模块数 / 实跑 / 用例数 / 失败数 / 缺失 / 有豁免 / 未豁免，每行还会列出未通过模块名。
  4. 看右栏「未通过模块」：未豁免的排最前，点进 exemption 补资料后重跑复审。
  5. 看「没跑到的模块」：最小集里有、所有轮次都没有结果的模块，需要重跑测试。

10.1 判定口径

项怎么算
期望模块按申请资料「是否带屏」选对应最小测试集清单，跑全才算过
已跑模块所有 report-N 的并集；每个模块以它最后出现的那一轮结论为准（增量补测只含失败子集）
用例数每个模块最后一轮 result/*.xml 的 tests 相加（不是 summary 根节点那个只算本轮的数）
真失败result="false" 且 status="run"；status=disable/skip 是被忽略用例，不算失败
豁免覆盖失败模块或测试套在 exemption\<分类>\ 下有同名目录即算已豁免
无屏方案跳过 DCTS 与 ACTS-VALIDATOR，不检也不算缺
「提示」不是错误。例如 ACTS-VALIDATOR 的用例数与参考口径差几条，会以灰字显示「提示（不影响结论）」，不会阻塞提交。

设置、托盘与单实例

11.1 外观

深色 / 浅色 / 跟随系统三选一，切换即时生效并记住选择。

11.2 关闭 = 收进托盘

  • 点窗口右上角关闭，窗口隐藏、进程继续跑，正在进行的测试与上传不受影响。
  • 托盘图标单击 / 双击，或右键菜单「显示主界面」，可以把窗口叫回来。
  • 真正退出：托盘右键菜单 →「退出」。

11.3 单实例

任何时刻只允许一个进程。窗口收进托盘后再双击 exe，只会把已有窗口叫出来，不会起第二个服务。

如果托盘里找不到图标，可能被系统折叠了：点任务栏的 ^ 展开隐藏图标区域。

报告归档与判卷口径

12.1 归档位置

每轮一份，编号递增不覆盖：

<设备目录>\report\ACTS\report-1\
                     report-2\      ← 补测轮
报告内：summary_report.xml  判卷依据
        summary_report.html 人看的报告
        result\*.xml        每个模块的用例明细
        log\                模块日志

12.2 各套件的报告格式本来就不一样

这是上游套件包自带的差异，不是 bug：

套件xdevice 版本报告长相
SSTS旧版details_report.html / failures_report.html / passes_report.html
ACTS / ACTS-VALIDATOR / HATS / DCTS新版static\（Vue 页）+ summary_report.html

应用在跑某个套件前会核对该套件 tools\ 里的 xdevice 版本指纹，不一致就整套重装，避免用错版本跑出错误格式的报告。

12.3 判卷

  • 以 summary_report.xml 为准：failures > 0 或整模块 ignored 都算失败。
  • 跑了一半中断的轮次，会用已完成模块的 result\*.xml 合成一份完整 summary 再归档，保证补测能接着跑。
  • 每个套件的执行命令、退出码、stderr 尾巴会写进本次运行目录下的 run.log，排查时先看它。

常见问题

跑测试报「已有任务正在执行」

同一时间只允许一个测试任务。等当前任务结束，或先点「停止测试」。资料任务（评测资料 / 豁免）与测试任务也互斥。

设备不在可选列表里

  • hdc list targets 看不到：检查线缆、USB 调试授权。
  • 能看到但显示「占用」：被别的测试或别的工具占着，先释放。
  • 显示「已选·不在线」：上次会话遗留的选择，点掉重新选。

SSTS 报告跟别的套件长得不一样

正常，见 12.2。SSTS 用旧版 xdevice，本来就是 details/passes 那套 HTML。

DCTS 全部 SoftBus 模块失败

先确认资源安装是否真的成功：设备上应存在 /data/local/tmp/dsoftbusTest、/data/local/tmp/socketdsoftbusTest、/data/test.wav，且 softbus_trans_permission.json 里有 com.communication.demo 条目。缺任一项说明 dcts_resource.bat 没跑完。

dcct 配不上 / 连的是旧设备

应用在组网前会先解绑盒子与被测设备上的历史连接（用 bm clean 清 dcct 数据）。若仍失败，人工在 dcct 里删掉「已连接设备」后重跑 DCTS。

豁免保存时提示 FIELD_VALUE_MISMATCH

平台对某些字符做了过滤（最常见是 < >）。应用现在填之前会换全角并给出「第 N 个字起不同」的定位信息；如果仍报错，把那一行报错发回来，说明平台又过滤了新字符。

应用启动没反应 / 有两个图标

  • 两个图标：旧版本遗留实例。关掉全部实例后重开一次即恢复单实例。
  • 启动没反应：先看托盘是否已有实例在跑（单实例会直接退出）；再检查是否被安全软件拦了。

想回滚到上一版

到 GitHub Releases 下载上一个版本的 XTS-Reporter-*-portable.exe 直接跑即可，应用不在系统里装任何东西。
